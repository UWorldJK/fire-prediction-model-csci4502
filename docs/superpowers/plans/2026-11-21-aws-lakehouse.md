# Western US Fire Lakehouse on AWS: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a cheap, serverless AWS lakehouse that runs until 2026-12-03. One CloudFormation deploy sets it up and one serverless job fills it with raw gridMET, MTBS and LANDFIRE data for the western US. Teammates then pull data, already combined across years, straight into their models, and push cleaned data back.

**Architecture:** There are two layers in one S3 bucket.
- `bronze/` is our raw data. It has two zones: `bronze/{source}/…`, files exactly as downloaded, and `bronze/integrated/…`, the same raw values combined across all years.
- `silver/` holds the cleaned, model-ready data the cleaning teammate pushes.

Everything is serverless:
- CloudFormation creates the bucket, the Glue catalog, an Athena workgroup, a CodeBuild job that runs ingest and integration in AWS (no laptop or EC2), one shared IAM role, and a budget alert.
- Study years are stack parameters.
- An HTML viewer is generated after every run, so you can see what's in the lake.

**Tech Stack:** Python ≥3.11, boto3, s3fs, awswrangler, xarray/netCDF4/zarr, geopandas/pyarrow (GeoParquet), rasterio/rioxarray; AWS S3, Glue Data Catalog, Athena engine v3, CodeBuild, CloudWatch Logs, IAM, Budgets, CloudFormation; pytest, moto[server], cfn-lint.

**Spec:** No separate spec file. The decisions agreed in the 2026-11-21 session are in "Design Decisions" below. Executors treat that section as the spec.

## Design Decisions (the spec)

| # | Decision | Value |
|---|---|---|
| D1 | Region of interest | `WEST_BBOX = (-125.0, 31.0, -102.0, 49.5)` as (west, south, east, north), EPSG:4326. Nothing from Alaska, Hawaii or the East. |
| D2 | Study years | **CloudFormation parameters** `StudyStartYear` (default `2002`) and `StudyEndYear` (default `2025`). They reach code through CodeBuild env vars `STUDY_START_YEAR` and `STUDY_END_YEAR`, and reach readers through stack outputs. To get more data, redeploy with new values and re-run ingest. Ingest is idempotent, so only the missing years download. |
| D3 | gridMET years | `range(StudyStartYear - 1, StudyEndYear + 1)`. The extra year gives January fires their 30-day lookback. |
| D4 | gridMET variables | `["pr", "tmmx", "tmmn", "rmax", "rmin", "vs", "th", "srad", "vpd", "erc", "bi", "fm100", "fm1000"]` from `https://www.northwestknowledge.net/metdata/data/{var}_{year}.nc` |
| D5 | MTBS | Composite perimeter zip (URL in `scripts/download_raw_data.py`). Keep fires whose `ig_date` year is in the study years and whose geometry intersects `WEST_BBOX`. Keep all `incid_type` values. |
| D6 | LANDFIRE | LFPS API `https://lfps.usgs.gov/api/job` with the layer groups below. 90 m resolution, native CRS (omit `Output_Projection`), tiles of 5.0° (20 tiles). LANDFIRE versions are fixed; they don't follow the study years. |
| D7 | Bronze is raw | Bronze changes only the spatial and temporal subset and the compression. Source variables, raw stored values (gridMET packed ints with `scale_factor`), units, CRS and columns are unchanged. `bronze/integrated/` follows the same rule; it only concatenates or mosaics. |
| D8 | Integration (combine all years) | gridMET: one Zarr store per variable, all years on `day`. MTBS: union of all snapshots, deduplicated on `event_id`, latest snapshot wins. LANDFIRE: one Cloud-Optimized GeoTIFF per layer, mosaicked from tiles, plus a reader that stacks fuel versions on a `version` dimension. Integration stores can be rebuilt from bronze raw at any time. |
| D9 | Layers | Two only, **bronze** (ingest/integrate) and **silver** (cleaning teammate). No gold, no Iceberg. Silver tables are partitioned Parquet registered in Glue, and gridded silver is Zarr. |
| D10 | Serverless | No EC2, Redshift or Glue crawlers. Compute is CodeBuild `BUILD_GENERAL1_SMALL` for ingest and `BUILD_GENERAL1_MEDIUM` for integration (Zarr and COG mosaics need more memory). SQL is Athena, schemas are the Glue Data Catalog. The same CLI also runs on a laptop as a fallback. |
| D11 | Access | One IAM role, `FireLakehouseRole`, with full access to the lakehouse. Its trust policy allows the account and `codebuild.amazonaws.com`. Teammates are IAM users in `fire-lakehouse-team`, whose only permission is `sts:AssumeRole` on that role. |
| D12 | Region / lifetime | `us-east-1`. Live until 2026-12-03, then torn down with `infra/teardown.sh`. S3 versioning is **off** (cheaper, and teardown is clean). |
| D13 | Viewer | Self-contained `viewer/index.html`, regenerated by the `viewer` target after each run. It has no external scripts and no credentials. Teammates open it with `python -m lakehouse.viewer`, which downloads it and opens the browser. The bucket is never public. |
| D14 | Teammate UX | `from lakehouse import open_gridmet, read_mtbs, open_landfire, open_landfire_series, query, read_silver, write_silver, write_zarr, open_zarr` |

## Global Constraints

- Python `>=3.11`. CodeBuild runs 3.12, the team venv runs 3.13, so no 3.13-only syntax.
- All AWS clients come from `lakehouse.config.client(name)` or `lakehouse.config.s3fs_options()`, with `region_name="us-east-1"` and `endpoint_url=os.environ.get("FIRE_LAKEHOUSE_ENDPOINT")`. Tests point the endpoint at a moto server.
- Config precedence for bucket and study years: env (`FIRE_LAKEHOUSE_BUCKET`, `STUDY_START_YEAR`, `STUDY_END_YEAR`), then outputs of stack `fire-lakehouse`, then the defaults 2002/2025. No account IDs, emails or keys in the repo.
- Bronze raw objects are write-once. Ingest skips existing keys unless `--force` is passed.
- Each bronze object written (raw or integrated) produces one manifest record with `source, s3_key, source_url, sha256, bytes, downloaded_at (UTC ISO-8601), bbox, params (JSON string), git_sha`. Integrated records use `source = "integrated_<dataset>"`, `sha256 = ""` for Zarr directories, and `source_url = "s3://<bucket>/<input prefix>"`.
- Downloads stream to `<name>.part` and are renamed when complete. A partial file is never uploaded.
- Dependencies: `requirements-ingest.txt` is what CodeBuild needs (`boto3 s3fs awswrangler requests xarray netCDF4 h5netcdf zarr geopandas pyarrow shapely rasterio rioxarray`). `requirements.txt` includes `-r requirements-ingest.txt` plus the analysis libraries already there, plus `scikit-learn`, with the duplicate `geopandas` removed. `requirements-dev.txt` has `pytest pytest-mock requests-mock moto[server] cfn-lint`.

## Review Focus

1. **LFPS rejects a tile, or a job fails partway through the backfill.** Re-running skips finished tiles. Test `test_ingest_landfire_skips_completed_tiles` (Task 6).
2. **A gridMET file 404s or times out partway through a 325-file run.** The run logs it, continues, and exits non-zero at the end. Test `test_ingest_gridmet_continues_after_http_error` (Task 4).
3. **A download dies halfway.** No S3 object is created. Test `test_failed_download_uploads_nothing` (Task 2).
4. **Integration is re-run after a CodeBuild timeout or a study-year change.**
   - Equal years: no-op.
   - Later years added: append only those.
   - Earlier years added: rebuild.
   - It never duplicates days.
   - Tests `test_integrate_gridmet_*` (Task 7).
5. **A teammate forgets `AWS_PROFILE=fire-lakehouse`, or asks for years or layers that aren't in the lake.** They get `LakehouseAuthError` or `ValueError` listing what is available, not a botocore trace or an empty Dataset. Tests in Task 9.

gridMET rule (D8 and Review Focus 4). Let `have` be the years already in `{var}.zarr`, read from the `day` coord, and `want` the years with a raw file in bronze that fall inside `years`:

| Case | Action |
|---|---|
| `have == want` | No-op (counted as `skipped`) |
| `want` starts with `have` and extends later | Append each missing year in order with `to_zarr(append_dim="day")` |
| Anything else | Delete the store's keys, then rebuild year by year |

Open each year with `mask_and_scale=False`, rename its single non-`crs` var to the short code, and chunk `{"day": 366, "lat": 64, "lon": 64}`. Memory stays at one year at a time.

MTBS: read every `bronze/mtbs/snapshot=*/…parquet`, concatenate, sort by snapshot, run `drop_duplicates("event_id", keep="last")`, and write `INTEGRATED_MTBS_KEY`.

LANDFIRE: for each layer, download its group's tiles, select the band by description prefix (falling back to `layer_location`), `rasterio.merge.merge`, and write with `driver="COG"`, `compress="DEFLATE"`. Skip it if the integrated key exists and `force` is false.
